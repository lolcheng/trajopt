## 问题分析

### 潜在问题

1. **数值稳定性问题**：
   - 不同量纲的量混合可能导致梯度数值差异很大
   - 例如：位置梯度（~1 m）vs 力梯度（~10 N）vs 力矩梯度（~10 N·m）

2. **权重调整困难**：
   - 由于量纲不同，权重值难以直观理解
   - 例如：`W_AIRBORNE_PENALTY = 1000.0` 对于长度²的量纲是否合适？

3. **优化器收敛问题**：
   - 虽然启用了Ipopt的自动缩放，但可能不够充分
   - 不同量纲的变量可能导致优化器难以找到平衡

## 建议的改进方案

### 方案1：使用Ipopt自动缩放（当前方案，已部分实现）

**优点**：
- 实现简单，只需设置选项
- Ipopt会自动处理缩放

**缺点**：
- 可能不够精确
- 无法完全控制缩放因子

**当前状态**：✅ 已启用

### 方案2：手动归一化变量

**实现步骤**：
1. 定义归一化因子：
   - 位置归一化因子：`L_SCALE = 1.0`（米）
   - 力归一化因子：`F_SCALE = 10.0`（牛顿）
   - 角度归一化因子：`A_SCALE = 1.0`（弧度）

2. 在`get_starting_point`中归一化初始值：
   ```cpp
   x[i] = x_raw[i] / L_SCALE;  // 对于位置变量
   x[i] = x_raw[i] / F_SCALE;  // 对于力变量
   ```

3. 在`eval_f`、`eval_g`等函数中处理归一化：
   - 输入：归一化的变量
   - 计算：使用归一化的变量
   - 输出：归一化的目标函数和约束

4. 在`extractTrajectory`等函数中反归一化：
   ```cpp
   Xb[i] = x_scaled[i] * L_SCALE;  // 反归一化位置
   ```

**优点**：
- 完全控制归一化过程
- 可以针对不同变量类型设置不同的归一化因子

**缺点**：
- 实现复杂，需要修改多个函数
- 容易出错

### 方案3：归一化目标函数权重

**实现步骤**：
1. 定义参考值：
   - 参考长度：`L_REF = 1.0` m
   - 参考力：`F_REF = 10.0` N
   - 参考力矩：`T_REF = 10.0` N·m

2. 归一化权重：
   ```cpp
   // 轮子-地形距离：量纲为 m²，归一化权重
   W_WHEEL_TERRAIN_NORM = W_WHEEL_TERRAIN / (L_REF * L_REF);
   
   // 力平衡：量纲为 N²，归一化权重
   W_FORCE_BAL_NORM = W_FORCE_BAL / (F_REF * F_REF);
   
   // 力矩平衡：量纲为 N²·m²，归一化权重
   W_TORQUE_BAL_NORM = W_TORQUE_BAL / (T_REF * T_REF);
   ```

**优点**：
- 实现相对简单
- 权重值更容易理解

**缺点**：
- 需要选择合适的参考值
- 可能不够精确
